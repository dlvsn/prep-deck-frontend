# Prep Deck — клієнт

[English](README.md) · **Українська**

Десктопний застосунок Prep Deck: картки у вкладених темах, відповіді в Markdown з картинками,
інтервальні повторення й теми, якими можна ділитися з іншими людьми. Зроблений для Windows на
Electron; той самий рендерер працює і в браузері як вебверсія. Працює лише з
[prep-deck-backend](https://github.com/dlvsn/prep-deck-backend).

## Стек

- Electron 45, electron-vite, вікно без системної рамки з власним заголовком
- React 18, TypeScript (strict), React Router, TanStack Query, Zustand
- i18next (англійська й українська), CSS Modules на токенах теми (світла й темна, вісім акцентів)
- react-markdown з підсвіткою Shiki, dnd-kit
- nginx у Docker для вебверсії

## Що вміє

- **Теми**: дерево без обмеження глибини; створення, перейменування, перетягування для зміни
  порядку й вкладеності, видалення з підтвердженням, пошук через `Ctrl K`.
- **Картки**: сітка з фільтрами; перегляд картки й редактор з прев’ю Markdown; до п’яти картинок
  (вибрати, перетягнути або вставити через `Ctrl V`, змінити порядок, переглянути на весь екран);
  теги.
- **Спільний доступ**: діалог «Поділитися» дає вибрати цілу тему або окремі підтеми, запросити за
  email чи username, показує, хто має доступ і які запрошення чекають, і керує публічним
  посиланням. «Спільні зі мною» показують чужі теми, згруповані за власниками, з «Копіювати до моїх
  тем» і «Вийти». Посилання `prepdeck://topic/<токен>` відкривають застосунок.
- **Практика**: екран «Скоро буде», доки практику не зроблено.
- **Акаунти**: вхід, реєстрація з кодом на email, сесія в сховищі ОС (DPAPI) з тихим оновленням;
  тема, акцент і мова синхронізуються з сервером.
- **Адаптив**: від портретного вікна 360 px (нижня панель вкладок, діалоги на весь екран) до
  широкого екрана.

## Запуск

### Десктопний застосунок, крок за кроком

Десктопний застосунок запускається на Windows просто з коду; інсталятора поки немає. Потрібні:

- Windows 10 або 11
- [Node.js 22 LTS](https://nodejs.org) (npm іде разом із ним)
- [Docker Desktop](https://www.docker.com/products/docker-desktop/), щоб запустити бекенд
- Git

**1. Отримай обидві частини.** Клієнту потрібен бекенд, тож склонуй їх поруч:

```
git clone https://github.com/dlvsn/prep-deck-backend.git
git clone https://github.com/dlvsn/prep-deck-frontend.git prep-deck-client
```

**2. Запусти бекенд** (разом із базою й поштовою пасткою) у Docker. Спершу відкрий Docker Desktop,
потім:

```
cd prep-deck-backend
docker compose up -d --build
```

Перша збірка триває кілька хвилин. Бекенд готовий, коли
http://localhost:8080/api/auth/username-available?username=test відповідає `"success":true`.

**3. Встанови клієнт.** У другому терміналі:

```
cd prep-deck-client
npm install
```

Заодно один раз завантажиться сам Electron (близько 100 МБ).

**4. Вкажи адресу бекенду.** Скопіюй приклад налаштувань:

```
cp .env.example .env
```

(`cp` працює і в PowerShell.) Типове `VITE_API_URL=http://localhost:8080/api` — це бекенд із
кроку 2; міняй, лише якщо бекенд працює деінде.

**5. Запусти.**

```
npm run dev
```

Відкриється вікно Prep Deck. Термінал не закривай: якщо закрити його або натиснути `Ctrl C`,
застосунок закриється. Зміни в коді одразу з’являються у вікні.

**6. Увійди.** Створи акаунт; код підтвердження прийде в Mailpit на http://localhost:8025 (справжні
листи не надсилаються). Потім створи тему й перші картки.

**Наступного разу** потрібні лише кроки 2 і 5: `docker compose up -d` у `prep-deck-backend` (якщо
контейнери зупинені) і `npm run dev` тут.

**Посилання для доступу** (`prepdeck://topic/…`): застосунок реєструє цей тип посилань у Windows
під час кожного запуску, тож після першого `npm run dev` таке посилання відкриває застосунок.
Посилання також можна вставити в «Спільні зі мною».

**Якщо щось пішло не так**

- *У вікні «Немає з'єднання»*: бекенд не запущено (`docker compose ps` у `prep-deck-backend`), або
  `VITE_API_URL` у `.env` вказує не туди. Після зміни `.env` перезапусти `npm run dev`.
- *`npm install` падає під час завантаження Electron*: запусти ще раз; за проксі задай
  `ELECTRON_MIRROR` або проксі для npm.
- *Немає листа з кодом*: відкрий http://localhost:8025; Mailpit перехоплює всі листи.

Зібраний застосунок (`npm run build`, потім `npm run preview`) відкриває свою сторінку з диска, а
бекенд поки не приймає запити з такої сторінки. Користуйся `npm run dev`, доки не з’являться
інсталятор для Windows і цей дозвіл.

### Налаштування

| Змінна | Що задає |
| --- | --- |
| `VITE_API_URL` | Бекенд, напр. `http://localhost:8080/api` |
| `VITE_FORCE_ROLE` | Лише для розробки: «Мої теми» приходять з цією роллю (`viewer`, `editor`), щоб перевірити екрани лише для перегляду |

### Вебверсія

```
npm run dev:web
```

відкриває той самий застосунок на http://localhost:5173. Або запусти його в контейнері
(`Dockerfile`, `docker-compose.yaml`): він збирається Vite і віддається nginx на
http://localhost:8081:

```
docker compose up -d --build
```

`VITE_API_URL` вшивається в збірку; береться з `.env` або за замовчуванням
`http://localhost:8080/api`. Compose бекенду вже дозволяє запити з `localhost:8081`. Сам
десктопний застосунок — програма для Windows і в контейнері не запускається.

### Скрипти

| Скрипт | Що робить |
| --- | --- |
| `npm run dev` | Десктопний застосунок у режимі розробки |
| `npm run dev:web` | Вебверсія в режимі розробки |
| `npm run build` | Перевірка типів, потім збірка десктопного застосунку в `out/` |
| `npm run build:web` | Збірка вебверсії в `out/web` |
| `npm run typecheck` | Перевірка TypeScript для main, preload і renderer |
| `npm run i18n:check` | Падає, якщо в `en.json` і `uk.json` різні ключі |

## Структура коду

```
src/main        Electron main: вікно, збережені розмір і положення, safeStorage, посилання prepdeck://
src/preload     міст window.prepDeck (типи в src/shared/bridge.ts)
src/renderer    звичайний вебзастосунок; до хоста звертається лише через app/platform.ts
  app/          маршрути, оболонка, сесія, синхронізація налаштувань, deep link
  api/          HTTP-клієнт, типи, по репозиторію на кожен розділ
  features/     auth, topics, cards, share, practice, settings
  ui/           спільні компоненти й іконки
  theme/        токени; i18n/ en і uk
```

Правила (жодного тексту в коді, жодних кольорів у компонентах, одне місце для прав, шари діалогів) —
у [CLAUDE.md](CLAUDE.md).
